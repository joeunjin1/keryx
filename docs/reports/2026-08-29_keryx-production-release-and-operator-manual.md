회사소개에는 **“스토리가 있는 제품을 기획하여 공급합니다.”**라는 메시지와 KERYX의 *kḗrux* 유래가 적용되었습니다. KERYX는 항상 대문자로 표기하고, 케릭스 / KERYX / 凯瑞의 승인된 명칭 규칙을 유지합니다. 중국 측 법인 정보는 공개 화면에 표시하지 않습니다.

> **공개 반영 원칙:** 운영자가 IP·캐릭터·콘텐츠 또는 판매 조건을 `공개`로 전환하면 해당 공개 API를 통해 공개 화면에 반영됩니다. 초안·보관 상태와 내부 원가·공장 연락처 등 운영 정보는 공개 화면에 노출하지 않습니다.

## 3. 운영자 접근 전제

운영 콘솔은 공개 주소와 분리되어 있으며, 로그인한 사용자의 `user_profiles.kind` 값이 `admin`인 경우에만 접근할 수 있습니다. 이 기준은 기존 관리자 권한 모델을 그대로 사용합니다. 비로그인 상태에서는 운영자 화면과 API 모두 로그인 화면으로 전환되며, 비밀번호·사용자 ID·API 키·시크릿은 이 문서에 기록하지 않습니다.

| 구분 | 운영 기준 |
|---|---|
| 관리자 홈 | `https://www.keryx.kr/admin` |
| 권한 전제 | 로그인 + `user_profiles.kind = admin` |
| 비로그인 운영 화면 | `/login?next=...`로 HTTP 307 전환 |
| 기존 직원·MD·바이어·공장 B2B 영역 | 기존 역할별 경로와 데이터는 보존, 이번 공개 구조 개편으로 삭제하지 않음 |
| 화면 언어 | 신규 공개·관리자 UI는 한국어/중국어 전환을 적용 |

## 4. 운영자 핵심 메뉴와 업무 범위

### 4.1 IP·캐릭터·콘텐츠 관리

| 주소 | 등록·수정 가능 데이터 | 공개 반영 규칙 |
|---|---|---|
| [IP·캐릭터·연재 등록](https://www.keryx.kr/admin/ip-studio) | IP명, 슬러그, 한국어·중국어 소개, 세계관, 대표·배너 이미지, 정렬 순서, 상태 | IP 상태를 `공개`로 전환해야 `/ip`에 노출 |
| 동일 화면의 캐릭터 관리 | 캐릭터명, 역할, 프로필, 이미지, 정렬 순서, 공개 상태 | 공개 IP 안에서 공개 캐릭터만 노출 |
| 동일 화면의 콘텐츠 관리 | 동화·웹툰·소설 등 콘텐츠 유형, 제목, 슬러그, 본문, 커버, 정렬 순서, 공개 상태 | 공개 IP와 공개 콘텐츠가 결합될 때 공개 허브에 표시 |
| 동일 화면의 미디어 업로드 | 이미지·영상·PDF 등 연결 파일과 용도 메타데이터 | 콘텐츠·캐릭터·IP에 선택적으로 연결 |
| [운영 이력](https://www.keryx.kr/admin/operator-activity) | 누가 언제 어떤 IP·캐릭터·콘텐츠·미디어 변경을 수행했는지 확인 | 운영자 전용 읽기 화면 |

**권장 등록 순서**는 `IP 기본 정보 → 캐릭터 → 세계관 설명·대표 이미지 → 연재 콘텐츠 → 미디어 연결 → 초안 검토 → 공개 전환 → 공개 IP 화면 확인`입니다. 이미 공개된 내용을 바꿀 때에도 먼저 한국어·중국어 문구와 이미지 연결을 검토한 뒤 저장하십시오. 삭제 대신 보관 상태를 사용해 기존 콘텐츠의 참조 무결성을 유지합니다.

현재 공개 운영 데이터 API는 빈 배열을 반환할 수 있으며, 이때 `/ip`는 기존 소개 콘텐츠를 fallback으로 표시합니다. 이는 오류가 아니라 실제 운영자가 공개 상태 데이터로 교체하기 전의 안전한 초기 상태입니다. 임의 IP, 캐릭터, 스토리 이미지를 만들어 운영 DB에 넣지 않았습니다.

### 4.2 상품·옵션·스토어 판매 조건 관리

| 주소 | 등록·수정 가능 데이터 | 주의 사항 |
|---|---|---|
| [전체 상품 데이터](https://www.keryx.kr/admin/products) | 전체 상품 목록 조회·관리 | 기존 B2B 상품 데이터와 신규 상품을 함께 관리 |
| [새 상품 등록](https://www.keryx.kr/admin/products/new) | 상품명, 한국어·중국어 설명, IP 연결, 규격·소재, 이미지, 태그, MOQ, 박스 규격, 무게, 리드타임, 초기 재고·판매 조건 | 실제 상품 정보만 입력하며 가짜 가격·재고 금지 |
| [스토어 상품 공개](https://www.keryx.kr/admin/retail-products) | 공개 여부, 원화 판매가, 스토어 재고, 배송 정책·배송비, 판매 상태, 공개용 한국어·중국어 설명 | 판매 조건이 모두 준비된 상품만 `/shop`에 노출 |
| [스토어 가격 변경 승인](https://www.keryx.kr/admin/retail-price-requests) | 기존 판매가 변경 요청 검토·승인·반려 | 요청자 본인은 직접 승인할 수 없음 |
| [운영 이력](https://www.keryx.kr/admin/operator-activity) | 상품 생성·판매 설정 변경·가격 요청·승인 이력 확인 | 운영자 전용 |

상품 등록 시에는 먼저 **IP 연결 여부**, 상품명과 한국어·중국어 설명, 이미지, 규격·소재를 확인합니다. 그 후 스토어에서 실제 판매할 상품에 한해 판매가·배송 정책·배송비·판매 재고·판매 상태를 입력하고 공개합니다. 공개를 선택하면서 판매가가 비어 있으면 저장할 수 없도록 설계되어 있습니다.

기존 판매가를 바꾸는 경우에는 판매 설정 화면에서 직접 금액을 덮어쓰지 않습니다. **가격 변경 요청을 등록한 뒤, 다른 관리자**가 가격 변경 승인 화면에서 승인 또는 반려해야 합니다. 이는 요청자와 승인자를 분리하는 DB 규칙이며, 가격 변경 요청·검토 결과도 운영 이력에 남습니다.

### 4.3 주문·발주·샘플 구독 운영

| 주소 | 운영 업무 | 완료 기준 |
|---|---|---|
| [주문 전 발주 상품](https://www.keryx.kr/admin/preorder-purchase) | 발주 전 품목, 수량, 목표 단가, CBM, 진행 상태, 메모 관리 | 품목·수량·상태가 실제 계획과 일치 |
| [스토어 주문·배송](https://www.keryx.kr/admin/retail-orders) | 스토어 주문 확인, 출고 준비·발송·배송 완료 상태 관리 | 허용된 순서로만 상태 전이 |
| [샘플 구독자 관리](https://www.keryx.kr/admin/b2b-subscribers) | 구독 신청자와 사업자 확인 상태·관심 정보 검토 | 사업자 확인과 안내 대상 분류 완료 |
| [신상품 안내 발송](https://www.keryx.kr/admin/weekly-report) | 검토된 구독자 대상 신상품·샘플 안내 운영 | 실제 발송 전 대상·내용 재확인 |
| [샘플 요청 관리](https://www.keryx.kr/admin/samples) | 기존 B2B 샘플 요청 업무 | 기존 요청 이력과 상태 보존 |

주문 전 발주는 실제 발주 확정 전에 수량·목표 단가·CBM·상태를 관리하는 별도 큐입니다. 일반 소매 주문과 섞지 않고, 구매 확정 또는 발주 전환 시 해당 기록을 추적합니다. 스토어 주문 상태는 기존 DB 함수가 허용한 상태 전이만 사용하며, 상태 변경 시 운영 이력에도 남습니다.

샘플 구독은 무조건적인 대량 발송 기능이 아닙니다. 신청자의 관심 정보와 사업자 확인 상태를 먼저 검토하고, 안내 대상이 확정된 후 신상품·샘플 정보를 운영합니다. 개인정보는 기본적으로 최소 열람 원칙을 적용하고, 필요한 운영 행위만 이력으로 남겨야 합니다.

## 5. 운영 이력과 데이터 무결성

새 운영 콘솔은 운영 동작을 `operator_activity_log`에 남기도록 구성했습니다. IP·캐릭터·콘텐츠·미디어·상품·주문 전 발주뿐 아니라 이번 Production 반영에서 스토어 판매 설정 변경, 가격 변경 요청, 가격 승인·반려, 주문 상태 변경도 이력 경로에 포함됐습니다.

| 운영 동작 | 기록 상태 | 확인 위치 |
|---|---|---|
| IP 생성·수정·보관 | 기록 | `/admin/operator-activity` |
| 캐릭터 생성·수정·보관 | 기록 | `/admin/operator-activity` |
| 연재 콘텐츠 생성·수정·보관 | 기록 | `/admin/operator-activity` |
| 미디어 업로드 | 기록 | `/admin/operator-activity` |
| 신규 상품 등록 | 기록 | `/admin/operator-activity` |
| 주문 전 발주 생성·수정·보관 | 기록 | `/admin/operator-activity` |
| 스토어 판매 조건 변경 | 기록 | `/admin/operator-activity` |
| 판매가 변경 요청·승인·반려 | 기록 | `/admin/operator-activity` |
| 스토어 주문 상태 변경 | 기록 | `/admin/operator-activity` |

**실제 운영 시 최초 점검 절차**는 다음과 같습니다. 관리자가 실제 IP 또는 실제 상품 하나를 초안으로 등록한 뒤 공개 전환하고, 해당 공개 화면에서 반영을 확인합니다. 이어서 운영 이력 화면에서 생성·수정 기록이 남았는지 점검합니다. 이때 실상품 판매가·재고·주문은 대표가 제공한 실제 데이터만 사용하십시오. 테스트가 필요하면 운영 데이터와 명확히 구분된 전용 테스트 데이터를 먼저 승인받아 사용해야 합니다.
