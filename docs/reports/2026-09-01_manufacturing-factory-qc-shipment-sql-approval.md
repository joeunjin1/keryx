# KERYX 제조 프로젝트 — 공장 실행·QC·출하 승인 SQL 보고서

**작성일:** 2026-09-01 GMT+9
**적용 대상:** KERYX Production Supabase
**상태:** 실행 전 승인용 SQL 준비 완료
**변경 유형:** 신규 테이블·RLS·함수 추가만 수행하는 무파괴 확장

## 결론

본 SQL은 기존 바이어 제품 요청과 운영자 프로젝트 콘솔에 이어, 선택된 공장이 자기 제조 프로젝트의 진행을 제출하고, QC 담당자가 사진·문서 증빙을 남기며, 운영자가 검토된 선적 서류를 바이어에게 공개하는 실행 단계를 추가한다. 기존 `sellers`, `factories`, `service_requests`, `sample_reports`, `orders`, `b2b_subscribers`, IP·스토어·소매 주문 데이터는 변경하거나 삭제하지 않는다.

> 공장 후보를 바이어 또는 다른 공장에 공개하지 않고, 한 프로젝트에 활성 공장 배정은 하나만 허용한다. QC 완료는 사진·문서 증빙이 하나 이상 연결된 경우에만 가능하다.

## 추가 객체와 역할

| 구분 | 신규 객체 | 주요 목적 | 접근 원칙 |
|---|---|---|---|
| 공장 배정 | `manufacturing_project_factory_assignments` | 운영자의 공장 후보·활성 배정·해제 기록 | 운영자만 활성화, 공장은 자기 활성 배정만 확인 |
| 공장 실행 | `manufacturing_factory_execution_updates` | 자재·샘플·생산·포장·이슈 진행 업데이트 | 공장은 자기 활성 프로젝트만 제출, 운영자 검토 후 바이어 공개 |
| QC | `manufacturing_qc_reports` | 생산 전·중·출하 전·컨테이너 검수 | 배정된 QC 담당자 또는 운영자 처리 |
| QC 증빙 | `manufacturing_qc_evidence` | 사진·영상·측정·문서와 QC 보고서 연결 | 증빙 없는 QC 완료 금지 |
| 선적 | `manufacturing_shipments` | 선적 준비·서류 검토·운송·도착 상태 | 운영자만 작성·공개 |
| 선적 서류 | `manufacturing_shipment_documents` | BL·CO·내륙/해상 운임 인보이스·상업송장·패킹리스트 | 운영자 승인 뒤 바이어에만 다운로드 허용 |

## 보안·무결성 통제

| 위험 | SQL 통제 |
|---|---|
| 공장이 타 공장 또는 바이어 프로젝트를 보는 문제 | `factories.shared_login_user_id = auth.uid()` 기준의 활성 공장 배정 RLS |
| 바이어가 공장 후보·원가·내부 메모를 보는 문제 | 바이어는 공개된 공장 업데이트·승인 QC·승인 선적 서류만 조회하며, 원가 테이블과 공장 후보 테이블은 미노출 |
| 공장이 자신의 업데이트를 임의로 공개·승인하는 문제 | 제출은 `submitted`·비공개 상태로만 가능, 공개·검토는 운영자 경로만 수행 |
| QC가 사진 없이 완료되는 문제 | `keryx_submit_manufacturing_qc_report`가 증빙 레코드 최소 하나를 DB에서 강제 확인 |
| 선적 서류의 제품명 불일치 | 한국어·영문 제품명을 별도 저장하고 영문 입력 출처를 기록, 중국어 제품명은 선적 서류 필드에 저장하지 않음 |
| 브라우저에서 테이블을 직접 변경하는 문제 | 신규 6개 테이블의 `anon`·`authenticated` 기본 권한을 회수하고, 검증된 서버 API·제어 함수만 변경 경로로 사용 |

## 파일 보관

기획·샘플·QC·선적 파일은 이미 Production에 적용된 비공개 `manufacturing-project-private` 버킷에 연결한다. 공개 URL을 발행하지 않으며, 바이어·공장·운영자 본인의 프로젝트 권한을 서버에서 검증한 뒤 단기 서명 URL로만 열람·다운로드한다.

## 상태 흐름

| 역할 | 입력 항목 | 완료 조건 | 바이어 노출 |
|---|---|---|---|
| 운영자 | 공장 배정·검토 메모 | 활성 공장 1곳 선택 | 미노출 |
| 공장 | 진행 유형·진행 메모·사진/PDF | `submitted` 상태 제출 | 운영자 검토 전 미노출 |
| QC 담당자 | 검수 단계·수량·판정·결함 설명·증빙 | 사진·문서 1건 이상 연결 후 제출 | 운영자 승인 시 요약·증빙 노출 |
| 운영자 | QC 승인·공개 요약 | 제출된 QC만 승인 | 승인된 경우에만 노출 |
| 운영자 | 선적 방법·참조번호·서류 | 서류 유형·영문 제품명·승인 상태 입력 | 승인 서류만 노출 |

## 실행 전 검증

정적 검증에서 트랜잭션 시작·종료 각 한 건, 신규 테이블 여섯 개, RLS 정책 스물한 개, 공장 활성화·QC 제출·QC 승인 등 제어 함수 여섯 개와 권한 회수 선언을 확인했다. 이 검증은 SQL 문법의 완전한 Production 실행을 대체하지 않으므로, Supabase SQL Editor에서 한 번 실행한 후 결과를 확인해야 한다.

## 실행 후 확인 항목

SQL 실행에 성공하면 다음 순서로 구현·검증을 진행한다.

1. 운영자 화면에서 공장 배정, QC 보고서 생성·검토, 선적 문서 관리 UI/API를 구현한다.
2. 공장 화면에서 자기 활성 프로젝트 목록·진행 제출·비공개 파일 첨부 UI/API를 구현한다.
3. QC 담당자 화면에서 증빙 파일 첨부·검수 보고서 제출 UI/API를 구현한다.
4. 바이어 프로젝트룸에서 승인된 진행 업데이트·QC 요약·선적 서류 다운로드만 표시한다.
5. 역할별 RLS·경로·한국어/중국어·모바일·감사 이력·Preview를 검증한다.
